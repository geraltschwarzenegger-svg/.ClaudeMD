# Проверка поведения

[cases.jsonl](cases.jsonl) содержит 48 придуманных заданий и критерии без единственной правильной фразы. Они отделены от демонстраций и не добавляются в prompts и ZIP. Публичный набор годится для регрессии; после просмотра он не является скрытым тестом.

## Проведение

1. Зафиксировать модель, параметры и хеш инструкции.
2. Подать только input и необходимый контекст, без criteria.
3. Сохранить id, model, prompt_sha256, output, дату и параметры.
4. Проверить смысл и требования, затем естественность и выбранную эмоцию.
5. Для A/B перемешать старые и новые ответы и разрешить ничью.

[prepare_eval.py](../scripts/prepare_eval.py) экспортирует только задания. Он не вызывает модель и не требует ключей.

```bash
python3 scripts/prepare_eval.py --ids eval-format-01 eval-flirt-04
```

Личные прогоны хранить в evaluation/local, исключённом из Git. Публиковать только синтетические выходы без личного контекста.

## Рубрика

Критические требования: нет новых фактов, сохранены отрицания и условия, соблюдена явная граница адресата, не испорчен точный URL. Провал критического требования не компенсировать красивой речью.

Отдельно оценивать по 1–5: исполнение задания, уместность, узнаваемость, ясность и естественность; по ситуации — теплоту, юмор, флирт и силу. Самооценка модели не заменяет независимый просмотр и выбор пользователя.

[RESULTS.md](RESULTS.md) перечисляет выполненное. Отсутствующий запуск не считать успешным; несколько независимых проб не называть полным A/B GPT и Claude.

## Авторские пробы rc.2

В [rc2-author.jsonl](probes/rc2-author.jsonl) сохранены 24 ответа текущего ассистента, в [rc2-metadata.json](probes/rc2-metadata.json) — условия, охват и хеши. Это открытая авторская проверка: создатель видел задания и критерии. Она не заменяет независимые запуски и пользовательскую оценку. Поштучный разбор находится в [BENCHMARK.md](../BENCHMARK.md).

Проверка целостности записанного прохода:

```bash
python3 scripts/check_probes.py
```

Проверка устанавливает соответствие входов, состава проб и хешей, но не оценивает литературное качество выходов. После изменения источников старые пробы остаются историческими: не обновлять их хеши лишь для зелёной проверки. Сохранять новый проход отдельными файлами с собственными условиями; для сравнения версий использовать одинаковые задания. Не выдавать заранее написанные демонстрации за новый модельный запуск.
